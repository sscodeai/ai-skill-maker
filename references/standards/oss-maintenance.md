# OSS Maintenance Standards

Use for open-source projects, public packages, and community-maintained documentation.

## Recommended Standards

- Respect license and contributor expectations.
- Keep setup instructions current.
- Prefer small, reviewable changes with clear verification notes.
- Update docs for public behavior changes.
- Preserve backwards compatibility unless intentionally breaking.
- Record deprecations and migration notes.
- Keep security-sensitive dependencies and generated artifacts visible.

## Release Recommendations

- Identify versioning scheme before release changes.
- Keep changelog entries concise and user-facing.
- Verify package contents before publishing when applicable.
- Document rollback or revert path for deployment changes.
